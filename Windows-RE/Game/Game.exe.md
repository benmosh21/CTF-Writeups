## שלב 1: זיהוי הבעיה הראשונית וניתוח סטטי
כדי להבין מדוע הקובץ מסרב לרוץ, התחלתי מאיסוף מידע בסיסי וניתוח סטטי של הקובץ:

* **בדיקת סוג הקובץ:** הרצת הפקודה `file .\game.exe` ב-PowerShell הראתה שהקובץ מזוהה בתור ספריה דינמית.

    ![alt text](<Screenshot 2026-05-24 151041.png>)
פלט פקודת file המראה שהקובץ הוא DLL


נבדוק עכשיו את הקובץ בתוך תוכנת Ida :
* **ניתוח ב-IDA Pro:** טעינת הקובץ ב-IDA אימתה שה-Entry Point הוגדר כ-`DllEntryPoint`.

    
    ![alt text](<Screenshot 2026-05-24 151339.png>)


    עם זאת, מבט בקוד הראה שמדובר באפליקציית חלונות רגילה לחלוטין. מצאתי קריאה לפונקציית האתחול `_set_app_type(_crt_gui_app)`, ולאחריה לולאת הודעות סטנדרטית של חלונות שכוללת שימוש ב-`RegisterClassW`, `CreateWindowExW` ו-`GetMessageW`.

    ![alt text](<Screenshot 2026-05-24 215119.png>)

**מסקנה:** ה-PE Header של הקובץ שונה בכוונת תחילה כדי שמערכת ההפעלה תחשוב שמדובר ב-DLL ותסרב להריץ אותו כתהליך עצמאי.

## שלב 2: תיקון ה-PE Header (Patching)
כדי לגרום למערכת ההפעלה להתייחס לקובץ כקובץ הרצה תקין, נדרשנו לערוך את דגלי המאפיינים (*Characteristics*) של הקובץ.

1.  פתחתי את הקובץ בעזרת הכלי **CFF Explorer** (ניתן לבצע גם דרך ה-Hex View ב-IDA).
2.  הלכתי למבנה ה-Headers של הקובץ: `Nt Headers` -> `File Header`.
3.  פתחתי את חלונית ה-`Characteristics`.
4.  הסרתי את הסימון של הדגל `File is a DLL`, שהורה למערכת ההפעלה להתייחס לקובץ כ-DLL במקום כקובץ הרצה.

    
    ![alt text](<Screenshot 2026-05-24 215931.png>)
    ---

5.  שמרתי את הקובץ החדש תחת השם `game1.exe`.

## שלב 4: זיהוי הספריה המקורית ותיקון טבלת הייבוא
כדי לגלות מה היה שמה המקורי של הספריה, היינו צריכים לבדוק אילו פונקציות הקובץ מנסה למשוך ממנה:

* פתחתי את הקובץ המתוקן ב-**CFF Explorer** וניווטנו ל-`Import Directory`.
* ברשימת הספריות, בחרתי בספריה המזויפת `FIXME.dll`.
* בטבלת הפונקציות (IAT) המשויכת אליה, מצאתי פונקציה יחידה: `PlaySoundW`.

    
    ![alt text](<Screenshot 2026-05-24 183510.png>)
    ---

* הפונקציה `PlaySoundW` היא פונקציית API מוכרת של Windows להשמעת קובצי קול. חיפוש מהיר בתיעוד הרשמי של מיקרוסופט (MSDN) אישר שהספריה שמייצאת את הפונקציה הזו היא `winmm.dll` *(Windows Multimedia)*.
* הבחנתי בכך שלמחרוזת `FIXME.dll` ולמחרוזת `winmm.dll` יש בדיוק את אותו אורך (9 תווים), מה שאומר שניתן לבצע Patch ישיר מבלי לפגוע במבנה הזיכרון של הקובץ.
* עברתי ל-**Hex Editor**, חיפשנו את המחרוזת `FIXME.dll` ודרסנו אותה עם המחרוזת `winmm.dll`.

## סיכום התוצאות
